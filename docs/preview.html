1. 요구사항

원했던 동작구현 방식
탭에 보이는 화면을 통째로 미리보기캡처 단계에서 가로 최대 240·320·480px 중 설정한 크기로 줄인다. 기본은 320px이며 세로는 원본 화면 비율을 따른다.
패널을 닫아도 같은 목록을 보기사이드 패널을 열면 패널에, 닫으면 채팅 오른쪽에 연결된 그룹을 보여준다. 같은 그룹의 캡처 연결과 마지막 프레임을 넘긴다.
세션마다 자기 탭 그룹 보기채팅 하나에 Chrome 탭 그룹 하나를 연결한다. 채팅을 바꾸면 미리보기와 선택 범위가 함께 바뀐다.
키보드로 탭을 정확히 골라 본문에 넣기처음에는 호형에서 좌우로, 그룹을 만든 뒤에는 세로 목록에서 상하로 고른다. Enter로 제목과 파비콘을 단 본문 칩을 삽입한다.
탭마다 권한을 허용하는 절차 없애기설치 시 Chrome이 표시하는 확장 권한을 사용한다. 개별 탭에서 아이콘을 눌러 캡처를 시작할 필요가 없다.
CPU 부담과 실제 갱신 속도 확인캡처 켜기·끄기, 형식과 FPS 제한, 카드별 실측 FPS, Chrome CPU 측정을 제공한다.

2. 사이드 패널과 우측 화면

두 곳의 카드와 키보드 선택 방식은 같다. 밝은 배경에 탭을 세로 한 줄로 배치하고, 제목과 도메인 옆에 실제 FPS를 표시한다. 스크롤은 가능하고, 잘린 카드가 더 있는 방향의 경계만 흐려진다.

캡처는 기본으로 켜진다. 사용자가 스위치를 끄면 같은 Chrome 프로필에 저장돼, Chrome이나 채팅을 다시 열어도 직접 켜기 전까지 꺼진 상태가 유지된다.

창을 최소화하거나 Chrome이 두 표시 화면을 모두 숨김으로 보고하면 캡처를 멈춘다. 창을 복원하고 화면이 보이면 캡처 스위치에 따라 재개한다.

다른 앱이 Chrome 창을 덮었을 때

로컬 보조 프로그램이 Chrome 창의 위치와 앞쪽 창의 범위를 확인한다. 미리보기가 있는 Chrome 창이 포커스를 잃으면 약 1초마다 확인하고, 창 전체가 두 번 연속 가려졌다고 판단되면 캡처를 멈춘다. 마지막 프레임을 남기고 일부가 다시 보이거나 Chrome 창에 포커스가 돌아오면 캡처가 켜진 상태에서 재개한다. 채팅 오른쪽과 확장 사이드 패널에 같은 규칙이 적용된다.

Mac은 Core Graphics, Windows는 Win32와 Desktop Window Manager에서 창의 위치와 앞뒤 순서를 읽는다. 로컬 보조 프로그램은 화면 이미지를 수집하지 않고 가려진 Chrome 창의 식별자만 보낸다. 창을 확실히 식별할 수 없거나 보조 프로그램이 응답하지 않으면 Chrome 자체의 숨김·최소화 상태를 사용한다. Windows용 코드는 현재 주 디스플레이의 Chrome 창을 연결하며, Windows 실기기 검증이 남아 있다.

일반 Chrome의 확인용 창은 다른 Mac 앱 창이 일부 가렸을 때 보임, 전부 가렸을 때 가려짐, 덮은 창을 치웠을 때 다시 보임으로 판정됐다. 자동 테스트로 가려진 동안 캡처가 멈추고 마지막 화면을 유지하며 다시 보이면 재개하는 동작을 확인했다.

  1. 사이드 패널 열림같은 채팅의 그룹 카드를 Chrome 패널에서 본다.
  2. 사이드 패널 닫힘미리보기와 첫 표시용 마지막 프레임이 채팅 오른쪽으로 넘어간다.
  3. 그룹 없는 채팅우측 미리보기 영역을 숨긴다. #을 누르면 입력창 위에 후보가 나타난다.

Chrome 탭 그룹에서 채팅 찾기

메시지 없이 그룹을 연 새 채팅에는 고른 칩의 이름으로 초기 제목을 붙인다. 첫 메시지를 보내면 요청 문구가 임시 제목이 되고, GPT-6 Luna가 만든 제목이 도착하면 왼쪽 목록, 채팅 상단과 연결된 Chrome 탭그룹에 반영한다. 나중에 그룹을 열거나 복원할 때도 저장된 채팅 제목을 사용한다. 제목 요청에 실패하면 임시 제목으로 계속 대화할 수 있다.

현재 보고 있는 탭이 탭룸 그룹에 속하면 Chrome 사이드 패널에 연결된 채팅 열기가 표시된다. 버튼을 눌렀을 때 해당 채팅으로 전환한다. 제목이 같은 그룹은 개별 ID로 구분한다.

탭 닫기와 다시 열기

  • 두 미리보기에서 카드에 마우스를 올리거나 키보드로 포커스하면 ×가 보인다. 누르면 해당 탭을 닫고 그 탭을 채팅의 복원 목록에서 뺀다.
  • 두 미리보기의 제목 옆에 겹친 탭과 × 모양의 그룹 닫기 아이콘이 있다. 그룹을 닫으면서 웹 주소와 순서를 이 채팅에 저장한다. 그룹 다시 열기로 복원한다.
  • 닫힌 그룹 대신 새 그룹을 만들려면 #으로 미그룹 탭을 고르고 메시지를 보낸다. 새 그룹 생성에 성공하면 그 채팅의 복원 기록도 바뀐다.
  • Chrome이나 확장 재시작으로 크롬의 그룹 연결 ID가 없어지면 이름만으로 그룹을 다시 연결하지 않는다. 같은 채팅의 복원 카드에서 탭을 열 수 있다.

자주 쓰는 탭 묶음

미리보기 제목 옆의 북마크 아이콘을 누르고 탭 묶음으로 저장에서 이름을 입력한다. 탭 주소·순서와 탭마다 보이는 정지 화면 한 장을 이 Mac에 저장한다. 캡처가 꺼졌거나 이미지를 받지 못한 탭에는 아이콘과 제목을 보여준다.

새 채팅 첫 화면의 저장된 탭그룹 이름에 마우스를 올리거나 키보드로 포커스하면 입력창 위의 호형에 저장 당시 화면이 보인다. 이름을 누르면 입력창에 그룹 칩이 들어가고, 전송하면 그 채팅에 그룹이 열린다. 같은 줄의 ×는 저장 목록의 묶음과 이미지에만 적용된다.

3. 호형과 세로 탭 선택

열린 그룹이 없을 때 #을 누르면 호형 옆에 현재 탭과 저장된 탭그룹이 표시된다. 기본은 현재 탭이다. 상하로 종류를 바꾸고 저장된 그룹은 위쪽의 이름을 좌우 키로 고른다. 아래 호형에 저장 당시 탭 화면이 보인다. Enter로 그룹 칩을 추가한다.

호형 선택기는 대화와 입력창 사이의 공간을 사용한다. 입력창은 같은 위치에 남고, 대화 끝을 보는 중에는 마지막 답변이 선택기 바로 위에 보인다. 이전 답변을 읽고 있으면 그 스크롤 위치를 유지한다. 두 선택 모드와 빈 목록에서 선택기 높이와 왼쪽 항목 위치가 같으며, 낮은 창에서는 호형을 줄여 대화 공간을 확보한다.

현재 Chrome 창에서 어떤 그룹에도 속하지 않은 웹 탭만 보여준다. 좌우 키로 후보 사이를 움직인다. 캡처가 꺼져 있어도 보이는 카드에는 첫 프레임을 한 장씩 요청한다.

그룹 연결 후 # · 세로 목록

현재 그룹의 탭만 상하 키로 고른다. 선택 카드는 왼쪽으로 살짝 나오면서 커지고, 나머지 카드는 오른쪽으로 조금 물러난다.

  • Chrome 상단의 실제 탭도 같은 창에서 표시할 수 있으면 임시 강조한다. 후보 순번 대신 탭 ID를 쓰므로 중간의 다른 그룹을 건너뛰어도 정확히 대응한다.
  • 두 선택기 모두 입력한 #을 지우거나 Esc를 누르면 선택이 닫히고 탭 강조가 풀린다. Enter는 공백 없이 커서 위치에 탭 칩을 넣는다. 칩 바로 뒤에서 Backspace를 한 번 누르면 칩을 삭제한다.
  • Shift+Enter는 고른 칩을 넣고 선택기를 유지한다. 저장된 탭그룹을 고르면 그룹 칩 하나가 들어간다.
  • 선택기가 닫힌 뒤의 Enter는 입력창의 버튼과 같다. 탭 칩과 공백만 있으면 그룹을 열고, 문구나 스킬 칩이 있으면 메시지를 보낸다. 같은 현재 탭을 여러 번 언급해도 그룹에는 탭 하나로 들어간다. Shift+Enter는 줄바꿈이다.

개별 탭은 본문의 각 위치에 칩으로 들어간다. 저장된 탭그룹은 그룹 이름을 단 칩 하나로 남는다. 에이전트에 보내는 메시지에서는 각 칩이 있던 위치에 [[tab:탭룸ID]]를 넣으며, 저장된 그룹과 사이트 칩은 그 위치에서 열린 탭들의 ID로 펼친다.

4. 캡처와 권한

사이트 종류에 관계없이 Page.startScreencast로 Chrome이 렌더링한 탭의 현재 화면을 받는다. 웹페이지의 보이는 영역 전체가 대상이다. 예를 들어 YouTube라면 동영상 재생 영역과 그 주변의 웹페이지 UI가 한 이미지에 들어온다.

  1. Chrome에서 캡처가로 최대 240·320·480px 중 하나를 선택한다. 세로는 화면 비율을 따르고, 설정에 따라 PNG나 JPEG 프레임을 받는다.
  2. 확장에서 전달캡처 대상 그룹과 표시 위치를 확인하고, 설정한 FPS 예산으로 프레임을 전달한다.
  3. 미리보기에서 표시이미지를 디코딩해 카드에 그린다. 표시 응답이 돌아오면 Chrome에 프레임 처리를 확인해 준다.

연속 프레임을 받는 방식과 도구가 필요할 때 한 장 찍는 스크린샷은 용도가 다르다. 미리보기는 PNG/JPEG를 고르더라도 같은 전체 탭 캡처 경로를 사용한다. FPS는 카드에 실제로 그린 프레임의 최근 2초를 기준으로 표시한다.

목록에서 보이는 카드만 캡처

채팅 오른쪽과 Chrome 사이드 패널은 목록과 겹치는 카드의 탭 ID를 확장에 전달한다. 첫 캡처는 보이는 카드부터 시작한다. 카드가 완전히 스크롤 밖으로 나가면 약 200ms를 기다린 뒤 Chrome 캡처를 종료한다. 스크롤, 창 크기 변경, 참조 선택에 따른 자동 스크롤에도 같은 기준을 사용한다.

마지막 이미지는 창별로 최대 약 8MB를 메모리에 보관한다. 카드가 다시 보이면 그 이미지 위에서 새 프레임으로 전환한다. 이미지를 기다리는 동안에도 이전 프레임의 비율을 유지한다. 자동 FPS나 작업 탭만 모드를 쓰면 해당 정책을 충족하는 가시 탭만 캡처한다.

Chrome의 tabCapture 영상 스트림은 사용자가 대상 탭에서 확장 기능을 실행하는 절차가 필요하다. 탭룸은 설치 때 확인하는 디버거 권한으로 화면을 받는다. 미리보기 중에는 Chrome이 디버깅 중이라는 안내를 표시할 수 있다. Chrome tabCapture · Chrome debugger

5. FPS와 CPU

신규 기본값은 PNG와 전체 탭 합계 30fps다. PNG는 작은 글자가 선명했다. 탭당 제한, 전체 합계 제한, 모든 탭 무제한, 자동, 작업 중인 탭만 30fps 중에서 선택할 수 있다. 설정값은 상한이며 원본 화면이 정지해 있거나 Chrome이 느리면 실제 FPS는 낮아진다.

자동은 전체 합계 30fps로 시작한다. PC 전체 CPU의 최근 5초 평균이 60% 미만이면 모든 탭 무제한, 60% 이상 80% 미만이면 전체 합계 30fps, 80% 이상이면 작업 중인 탭만 30fps를 적용한다. 높은 부하에는 즉시 대응하고, 낮은 부하가 10초 이상 유지되면 한 단계씩 복구한다.

작업 중인 탭만 모드에서는 브라우저 도구가 조작한 탭 한 개를 보여준다. 마지막 조작 뒤 2초간 유지하고, Chrome이 로딩 중이면 최대 8초까지 연장한다. 다른 카드는 같은 그룹의 마지막 화면을 남긴다.

채팅 위에 겹쳐 뜨는 모니터링에서 PC 전체 CPU, Chrome CPU, 실제 미리보기 합계 FPS와 현재 자동 단계를 확인한다. 모니터링은 기본으로 펼쳐져 있고 필요할 때 접을 수 있다. PC 전체 CPU는 Chrome 확장의 CPU 권한으로 측정한다.

6. 브라우저 작업 중 프레임 끊김 수정

미리보기와 브라우저 도구는 같은 탭의 Chrome 연결을 사용한다. 이전에는 도구 호출이 끝날 때 포커스 에뮬레이션을 끄면서, 미리보기가 뒤에 있는 탭의 프레임을 받기 위해 켜 둔 설정까지 풀렸다.

0.5.6부터 연결이 각 기능의 요청을 따로 기록한다. 미리보기나 브라우저 도구 중 하나라도 설정을 사용하는 동안에는 켜 두고, 모두 사용을 끝내면 해제한다. 에이전트가 별도로 화면 녹화를 시작해 캡처가 겹칠 때는 해당 미리보기를 잠깐 멈췄다가 재개한다.

7. 대화형 응답과 에이전트 가이드

에이전트가 일반 Markdown 답변 중간에 tabroom-ui 코드 블록을 넣으면 채팅이 그 부분을 대화형 화면으로 표시한다. 사용자가 조건을 직접 고르거나 값을 바꿔 비교할 수 있을 때 에이전트가 필요한 요소를 조합한다.

모듈역할
인터랙티브 UI 스킬인터랙티브 UI 스킬에서 응답 규격과 요소 목록, 예시를 읽는다. 에이전트는 필요할 때 load_skill에 tabroom-interactive-ui를 지정한다. 다른 앱에서 쓸 때는 렌더러 적용 방법을 참고한다.
응답 규격protocol.js가 완성된 JSON 블록의 버전, 요소, 초기값, 동작을 검사한다. 잘못된 블록은 원문을 접어서 보여주고 앞뒤 설명은 계속 읽을 수 있다.
화면과 상태render.js는 카드, 내부 탭, 펼치기, 여러 종류의 입력, 계산 결과, 검색·정렬·필터 표, 막대·선 차트와 버튼을 조합한다. 입력값은 메시지와 위젯 단위로 현재 브라우저 세션에서 유지한다.
사용자 동작클릭으로 복사, 초기화, 선택값 반영, 텍스트 내보내기, 채팅 입력창에 넣기를 할 수 있다. 사용자는 입력창에 들어온 내용을 확인한 뒤 직접 보낸다.

다른 에이전트에 붙일 때는 같은 스킬 본문을 제공한다. 채팅 화면에서는 완성된 답변 텍스트를 렌더러에 넘기고, 입력창에 넣기 동작에 해당 앱의 콜백을 연결한다. 모델이나 에이전트 서버를 바꿔도 같은 규격으로 화면을 그릴 수 있다.

일반 Chrome에서 확인한 동작

GPT-6 Luna가 가이드를 조회하고 만든 화면에서 수량을 2에서 4로 올리자 합계가 9,000원에서 18,000원으로 바뀌었다. 표에서 검색과 정렬이 작동했고, 버튼은 기존 초안 아래에 수량을 추가했다. 같은 탭을 새로고침해도 수량은 4로 유지됐다.

8. 툴 호출과 컨텍스트 사용량

browser_repl은 Chrome을 조작하고 browser_guide는 브라우저 설명서와 API 도움말을 조회한다. 브라우저 도구의 purpose는 대화 기록에 표시한다. load_skill은 스킬 이름만 받고 그 이름에 해당하는 한국어 문구를 표시한다.

처음 자동 주입되는 메인 지침은 브라우저 제어와 인터랙티브 UI 스킬을 언제 읽는지 안내한다. 에이전트는 필요한 본문을 load_skill로 읽는다.

에이전트는 현재 채팅에 연결된 Chrome 프로필을 자동으로 사용한다. 열린 그룹이 없는 채팅에서 웹 작업을 시작할 때는 openBrowserTab으로 열린 탭의 tabId를 createTabGroup에 전달한 뒤, 연결된 그룹 안에서 페이지를 읽거나 조작한다. 브라우저 스킬에 탭 열기와 그룹 만들기를 한 번에 실행하는 예제와 이미 연 탭을 다시 쓰는 방법을 제공한다.

탭룸 전용 App Server는 새 채팅과 다시 연 기존 채팅에서 외부 플러그인과 MCP 도구를 끈다. 브라우저 작업은 연결된 Chrome 탭 그룹에 적용되는 탭룸 REPL을 사용한다.

채팅 상단의 컨텍스트에 마우스를 올리거나 키보드로 포커스하면 App Server가 보고한 최근 모델 요청의 토큰을 확인한다. 캐시 입력과 추론 출력은 각각 입력과 출력에 포함된다. 새 채팅에서 탭룸이 기록한 지침, 대화, 브라우저 작업, 스킬·가이드 텍스트는 4바이트당 약 1토큰으로 표시한다. 이 추정은 이미지와 App Server 내부 자료를 제외하며, 컨텍스트가 압축되면 실측 내역만 표시한다.

9. 탭 참조와 미리보기 모션

호형 미리보기에서 입력창으로

Enter를 누르면 칩과 커서는 즉시 입력창에 놓인다. 선택한 카드의 복제본은 가로·세로 배치를 유지한 채 450ms 동안 한 속도 곡선으로 이동하고 작아진다. 파란 테두리와 프레임은 이동 중 옅어지고, 도착에서 칩으로 이어진다.

첫 탭 그룹이 연결될 때

전송 순간 입력창에 보이는 칩의 위치를 기록한다. 그룹 연결에 성공하면 일반 탭 칩은 대응하는 카드에, 저장된 그룹 칩은 그 묶음에서 연 첫 카드에 350ms 동안 이어진다. Chrome 사이드 패널이 열려 있으면 패널에서 도착 카드 높이를 측정한다. 칩은 그 높이를 향해 대각선으로 올라가며 채팅의 오른쪽 경계에서 옅어진다. 패널 카드는 같은 시작 시각을 기준으로 왼쪽에서 들어오고, 나머지 카드는 짧은 간격을 두고 나타난다.

기존 그룹에 탭이 추가될 때

에이전트가 탭을 추가하거나 사용자가 직접 그룹에 넣으면 Chrome 순서대로 카드를 삽입한다. 새 카드는 240ms 동안 6px 올라오며 또렷해진다. 보이는 기존 카드는 제자리를 부드럽게 내주고, 화면 밖의 추가로 스크롤이 이동하지 않는다. 초기 미리보기 프레임만 150ms에 걸쳐 나타난다.

세로 목록에서 참조 탭을 고를 때

선택 카드는 왼쪽 8px, 104% 크기로 강조한다. 다른 카드는 오른쪽 6px, 95% 크기로 정렬한다. 180ms 동안 전환하고, 상하 키를 누르면 먼저 새 카드에 선택 상태를 반영한다. 선택 카드가 가려질 때 필요한 만큼 스크롤한다.

운영체제에서 동작 줄이기를 사용하면 애니메이션 없이 해당 상태를 표시한다.

채팅 입력창에서 사이트 검색

현재 탭, 저장된 탭그룹, 검색은 같은 높이와 메뉴 위치, 키 안내를 사용한다. 검색 중 입력창의 활성 #검색어에 연한 파란 배경을 입힌다. ↑와 ↓로 편집 커서가 이동하지 않으며, 한글 조합 중에는 입력기가 키를 처리한다. 선택기를 닫으면 검색어는 남고 배경색은 사라진다.

# 뒤에 검색어를 쓰면 주소 추천과 딥링크가 한 줄에 나타난다. 좌우 키로 선택하면 아래에서 해당 사이트의 제목, 주소와 정지 화면·설명을 볼 수 있다. 같은 주소가 두 검색에 잡히면 한 항목으로 합친다. Enter로 사이트 칩을 넣고 Shift+Enter로 연속해서 추가한다.

주소 추천은 Chrome의 자주 방문하는 사이트를 사용한다. 첫 홈에서 방문 기록 권한이 필요하면 버튼을 표시한다. 설정에서도 변경할 수 있다. 한글 조합 중인 입력을 검색에 반영한다. 딥링크 호출은 300ms에 최대 한 번으로 제한하고 같은 검색어의 최근 결과를 재사용한다. 임시 딥링크 API는 등록한 실제 페이지 20개를 검색한다.

검색 예시는 #영화 예매, #오늘 박스오피스, #장보기, #맥북 구매, #오픈소스 AI 모델, #인공지능 논문이다. 입력을 보내거나 탭그룹 열기를 누르면 그 채팅의 그룹에서 선택한 사이트를 연다.

10. 에이전트 답변의 탭 참조 칩

에이전트는 자료를 확인한 탭의 탭룸 ID와 URL을 가능한 한 같이 남긴다. [[tab:ID URL]]은 두 값을, [[url:URL]]은 URL만, [[tab:ID]]는 탭 ID만 지정한다. 스킬은 특정 탭에 안내하거나 근거를 제시할 때 칩을 쓰도록 안내한다.

saveCitation({tabId, url})은 브라우저에서 읽는 시점의 탭, 문서 식별 정보, 제목과 주소를 저장한다. 에이전트는 도구가 돌려준 [[source:ID]]를 완성 답변의 관련 문장 옆에 넣는다.

출처 칩을 누르면 저장한 주소가 열린 탭으로 이동한다. 원래 탭이 다른 주소로 이동했다면 그 페이지를 유지하고 현재 그룹에 출처를 새 탭으로 연다. 칩을 다시 누르면 그 출처 탭을 재사용한다. 원래 탭이 닫혔고 재사용할 출처 탭이 없으면 기존 탭룸 ID로 복원한다. 주소 없이 탭 ID만 있는 칩은 그 탭의 현재 페이지로 이동한다.

브라우저 스킬은 답변에 보이는 사이트 이름이나 구체적인 화면 내용 뒤에 칩을 넣도록 안내한다. 숫자 ID는 칩과 도구 호출 안에만 넣는다. 출처에는 확인한 주소를 담고, 로그인처럼 열린 탭에서 사용자가 직접 이어서 처리할 경우에는 현재 탭을 가리키는 칩을 사용한다.

답변 완료 시 동일한 문서에서 정지 화면을 한 번 캡처한다. 답변 하나당 최대 8개 문서를 캡처하며, 이미지는 로컬에서 답변에 연결해 저장한다. 칩에 마우스를 올리면 제목과 도메인, 저장된 화면을 볼 수 있다. 캡처 OFF일 때 새 화면을 찍지 않는다.

11. 자주 쓰는 작업과 스킬

자주 쓰는 작업

새 채팅 첫 화면의 작업을 고르면 저장된 문장과 탭그룹 칩이 원래 순서대로 입력창에 들어간다. 편집 화면에서 작업 문구를 바꾸거나 저장된 그룹을 커서 위치에 칩으로 넣을 수 있다. 작업에 넣은 칩은 그룹 이름과 탭 주소를 순서대로 복사해 저장한다. 원본 묶음을 삭제한 뒤에도 칩을 포함해 전송하면 그 주소로 그룹을 열 수 있다.

에이전트는 save_quick_task로 같은 형식의 작업을 등록한다. quick-task-creator 스킬은 필요한 작업 문구와 브라우저 사용 여부를 확인한 뒤, 필요한 경우에만 칩을 함께 저장하도록 안내한다.

스킬 목록

입력창에서 /를 누르면 스킬 목록이 열린다. 브라우저와 인터랙티브 UI는 필요할 때 에이전트가 읽는 자동 스킬이다. 자주 쓰는 작업 만들기, 스킬 만들기, 직접 만든 스킬은 선택해서 본문에 $스킬-ID로 넣을 수 있다.

직접 만든 스킬은 현재 Chrome 프로필에 Markdown으로 저장한다. 메인 지침은 에이전트에게 list_skills로 목록을, load_skill로 본문을 읽고, 스킬 만들기 요청에는 create_skill로 등록하도록 안내한다.

12. 홈과 채팅 목록

첫 화면, 탭룸 로고, 새 채팅은 같은 입력 화면을 연다. 홈의 탭룸 세션 ID는 첫 메시지를 보내거나 탭그룹을 성공적으로 열 때 저장된다. 작성 중인 홈에서 새 채팅을 다시 눌러도 입력과 선택한 칩을 유지한다. 기존 채팅 링크는 해당 대화를 바로 연다.

홈의 자주 방문하는 사이트에는 Chrome이 제공하는 순서대로 사이트를 최대 4개 표시한다. 사이트를 고르면 이름과 Chrome 로컬 파비콘을 단 탭 하나짜리 칩이 입력창에 들어간다. 사이트 목록은 Chrome의 topSites에서 읽으며, 메시지를 보낼 때 에이전트에는 선택한 탭의 참조를 전달한다.

메시지 없이 탭그룹 열기

탭그룹 열기는 지금 열린 탭을 묶고, 고른 저장된 그룹과 사이트의 탭을 같은 그룹에 연다. 홈에서는 그룹이 열린 뒤 왼쪽에 채팅이 표시되며 대화 기록은 빈 상태다. 기존 채팅에서는 현재 채팅에 그룹을 연결한다. 여러 그룹을 따로 열어두면 나중에 왼쪽 목록에서 각각의 채팅으로 돌아갈 수 있다.

첫 실제 메시지에서 Codex 대화를 시작하고 이미 연결된 그룹을 사용한다. 탭룸 채팅과 Chrome 그룹 연결에는 홈에서 생성한 탭룸 세션 ID를 사용한다. Codex 자체 대화 ID는 첫 메시지를 처리할 때 할당된다.

왼쪽 채팅 목록에는 열린 그룹과 복원할 수 있는 그룹의 아이콘을 최대 3개와 전체 탭 수를 표시한다. 열린 그룹은 Chrome 탭 바의 그룹 색으로 감싸고, 복원할 수 있는 그룹은 옅은 회색으로 표시한다. 아이콘이나 개수에 마우스를 올리거나 채팅 행에 키보드로 포커스하면 탭 제목을 볼 수 있다. 현재 보는 채팅은 행 전체가 강조된다. 닫힌 그룹은 해당 채팅에서 복원할 수 있다.
