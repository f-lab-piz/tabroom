## 2026-11-20 · 0.5.2

### Plan Input

[탭룸 배포와 세션별 탭 미리보기](../planning/spec-session-preview.md)의 갱신된 설치 권한 기준.

### Implemented

캡처에는 에이전트와 같은 Chrome 디버거 권한을 사용한다. Chrome이 그린 화면 전체를 320px PNG 프레임으로 보내고, 실제로 그린 프레임에서 FPS를 계산한다. 일반 에이전트 작업은 미리보기와 연결을 공유하고, 에이전트가 별도 화면 녹화를 하면 미리보기는 잠시 멈췄다가 재개한다. 설치 파일에서 `tabCapture`와 `activeTab` 권한을 제거했다.

### Test Coverage

세션별 캡처, 사이드 패널 이동, 다른 디버거와의 충돌 표시, 에이전트 연결 유지. Chrome 158의 임시 새 프로필에서 원본 탭을 누르지 않고 영상 재생 탭 3개와 정적인 탭 1개를 모두 그렸고 캡처를 끌 때 중단된 것을 확인했다.

### Test Command and Result

`node --test outputs/tabroom/tests/session-preview.test.mjs` 통과 3개. `node work/preview-v052/integration.mjs`는 권한 선언, 각 탭의 폭 320px, 움직이는 세 영상의 갱신, 정적 화면, 종료를 확인했다. 영상 탭당 실측 갱신 속도는 약 26fps였다.

### Decisions

Chrome의 동영상 녹화 경로는 정적인 탭에서 첫 재생 가능한 데이터가 10초 안에 도착하지 않았다. `Page.startScreencast`의 PNG 프레임 하나로 통일했다. 신규 설치 ZIP을 만들었으며 사용자의 기존 설치는 수정하지 않았다.

### Next Actions

사용자가 개발판을 직접 설치해 본다. Chrome 웹 스토어 심사 및 설치 권한 화면 검증과 CPU 비교는 별도 진행이 필요하다.

## 2026-11-20 · 0.5.3

### Plan Input

패널을 닫았을 때 우측 미리보기 복귀, 호형 선택기의 첫 이미지, 포맷과 FPS 비교.

### Implemented

같은 그룹을 볼 때 캡처 연결을 유지하고 마지막 프레임을 새 표시 위치로 넘긴다. 캡처가 꺼져 있을 때 호형 선택기를 열면 보이는 카드에 한 프레임씩만 요청한다. 환경설정에서 JPEG/PNG와 탭당, 전체 합계, 제한 없음 FPS를 선택할 수 있다.

### Test Coverage

사용자 일반 Chrome의 테스트 창에서 캡처를 끈 상태의 호형 카드 3개와 사이드 패널을 닫은 뒤 우측 카드 3개를 확인했다. 720p로 재생된 침착맨 긴 영상 3개로 다섯 조건의 Chrome 전체 CPU와 탭별 실제 FPS를 측정했다.

### Test Command and Result

`node --test outputs/tabroom/tests/session-preview.test.mjs` 4개 통과. 실제 Chrome 측정은 [CSV](../../탭룸-0.5.3-실제-Chrome-CPU.csv)에 기록했다. 20초를 목표로 했고 실제 구간은 연결 지연으로 약 24–38초였다. CPU 사용률과 FPS는 각각의 실제 경과 시간으로 계산했다.

### Decisions

탭당 30fps에서 JPEG와 PNG의 CPU 차이는 1.7%p였다. 글자 가독성을 기준으로 PNG를 기본으로 둔다. PNG 전체 합계 30fps는 탭당 30fps보다 CPU 사용률이 21.3%p 낮았으므로 신규 기본 제한으로 둔다. 저장된 기존 FPS 설정은 유지한다. WebP는 현재 쓰는 Chrome 캡처 명령의 공식 포맷에 포함되지 않아 실측에서 제외했다.

### Next Actions

설정에서 더 높은 미리보기 속도가 필요할 때 탭당 30fps를 선택할 수 있다.

### Implemented

Enter 전송과 Shift+Enter 줄바꿈, 파비콘·제목이 있는 본문 칩과 반복 참조를 적용했다. 그룹이 없는 채팅에서 대화할 수 있고, 에이전트가 미그룹 탭을 조회하거나 연 뒤 `createTabGroup`으로 현재 채팅의 그룹을 만든다. 이후에는 같은 응답 중에도 그룹 밖의 조회와 제어를 차단한다.

호형 및 그룹 미리보기 선택이 실제 Chrome 탭과 함께 움직인다. 공유 카드에 선택 강조와 스크롤 경계 흐림을 넣고 첫 그룹 연결 시 칩과 카드에 이동 모션을 적용했다.

### Test Coverage

사용자의 일반 Chrome에서 그룹 없는 전송과 실제 답장, Shift+Enter 줄바꿈, 그룹을 건너뛰는 동일 제목 탭 강조, 본문 순서와 반복 참조를 확인했다. 에이전트가 로컬 데모 탭을 열고 첫 그룹을 만든 뒤, 같은 응답에서 두 탭만 조회하고 새 탭 제목을 읽었다. 열린 사이드 패널에서 상하 키에 따라 Chrome 상단 강조가 움직이고 Esc에 해제됐다. 그룹 밖 직접 제어 차단과 접힌 그룹의 상단 강조 생략은 자동 테스트로 확인했다.

### Test Command and Result

`node --test outputs/tabroom/tests/*.test.mjs` 7개 통과. 실제 Chrome 158에서 위 시나리오를 확인했다. 설치 ZIP은 53개 파일의 무결성을 검증했다.

### Decisions

그룹 추가는 현재 채팅에 연결된 브라우저 도구의 명시적 동작이다. 사용자가 Chrome에서 직접 잡은 다중 선택은 보존하고 탭룸의 임시 강조만 정리한다.

### Next Actions

일반 Chrome에 0.5.4를 반영했다. 임시 브라우저 창을 닫고 원래 채팅 선택을 복원했으며, 탭룸 목록에 확인용 채팅 한 개를 남겼다.

## 2026-11-20 · 0.5.8

### Plan Input

대화에서 정한 자동 FPS 세 단계, PC 전체 CPU와 실제 합계 FPS, 현재 자동 단계 표시, 작업 탭과 마지막 화면, 창 최소화와 숨김 처리.

### Implemented

확장의 CPU API로 PC 전체 사용률을 읽는다. 자동 모드는 5초 평균의 60%와 80% 기준으로 무제한, 합계 30fps, 작업 중인 탭만 30fps를 적용한다. 여유가 10초 유지된 뒤 한 단계 복구한다. 실제 브라우저 조작이 들어오면 해당 탭만 캡처하고, 다른 카드는 마지막 이미지를 표시한다. 창이 숨겨지면 실시간 캡처를 정지한다.

### Test Coverage

일반 Chrome에서 CPU 수치와 자동 무제한 표시를 확인했다. 영상 세 개의 짧은 비교에서 모든 탭 합계 30fps와 작업 탭만 30fps의 Chrome CPU 평균은 각각 63.1%와 45.4%였다. 같은 구간의 PC 전체 CPU는 각각 19.9%와 27.9%였으므로 PC 전체 사용률 감소는 확인되지 않았다. A에서 B로 조작을 옮기면 B만 갱신됐으며, 최소화 때 프레임이 정지하고 복원 때 B가 다시 움직였다.

### Test Command and Result

`node --test outputs/tabroom/tests/*.test.mjs`에서 13개 통과. 고부하 단계와 수동 OFF 유지도 자동 테스트로 확인했다.

### Decisions

사용자가 FPS 설정에서 자동 또는 작업 중인 탭만을 선택한다. 작업을 시작하거나 끝내는 신호는 실제 브라우저 입력·탐색 명령을 기준으로 한다. 마지막 이미지는 현재 탭 그룹의 미리보기 메모리에 보관한다.

### Next Actions

일반 Chrome에 0.5.8을 반영했다. 설치 ZIP과 미리보기 HTML 안내에 새 동작을 반영했다.

## 2026-11-20 · 0.6.1

브라우저 프로필, REPL, 스킬·가이드 조회가 새 채팅에서 `purpose`를 요구한다. 실행 시 대화 기록에 한 줄을 추가한다. 새 채팅과 재개한 채팅의 초기 지침은 스킬을 언제 읽을지 안내하며, 턴 요청에는 메시지와 탭 참조만 보낸다. 두 `SKILL.md`는 프로젝트 패키지에 포함하고 기존 `guide`로 읽는다. 이전 채팅이 사용하는 기존 도구 규격은 제목과 조회 대상에서 문구를 가져올 수 있다.
