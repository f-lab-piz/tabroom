# 채팅 입력창의 `#` 사이트 검색

## Problem

채팅에서 사이트를 참조하려면 먼저 Chrome에서 사이트를 열거나 저장된 탭그룹을 찾아야 한다. 주소를 일부만 기억하거나 페이지가 하는 일만 알고 있으면 이 과정이 길어진다.

## Target User

채팅 입력창에서 키보드로 브라우저 탭을 참조하며, 방문한 사이트나 등록된 업무 페이지를 작업에 추가하려는 탭룸 사용자.

## User Value

주소 일부와 자연어 표현을 같은 입력창에서 쓸 수 있다. 선택한 결과가 문장 안의 칩으로 들어가므로 페이지를 먼저 찾기 위해 대화 흐름을 끊을 필요가 줄어든다.

## Use Cases

- `#n` 또는 `#네이버`로 Chrome이 알려준 사이트 후보에서 네이버를 골라 칩을 넣는다.
- `#사내 진료 시스템`으로 등록된 업무 페이지를 찾아 칩을 넣는다. 요청 문구와 함께 보내면 그 페이지가 채팅에 연결된 그룹에서 열린다.
- `#`만으로 현재 탭이나 저장된 탭그룹을 고르는 기존 방식도 계속 쓴다. 그룹이 열려 있으면 `#`만 입력할 때 오른쪽의 그룹 탭 선택기를 사용한다.

## Corner Cases

- `#검색어`에서 검색어를 모두 지우면 원래 선택기로 돌아간다. `#`을 지우거나 `Esc`를 누르면 선택기를 닫고 진행 중인 검색을 폐기한다. `Esc`는 이미 입력한 글자를 보존한다.
- 한국어 조합 중 Enter는 조합을 완료하는 데 사용한다. 조합 완료 후 다음 Enter로 선택한다. 검색 결과가 없는 상태에서 선택기에 Enter를 눌러도 메시지를 보내지 않는다.
- 딥링크가 늦거나 실패하면 주소 추천은 바로 쓸 수 있다. 이미 강조한 후보는 딥링크가 도착해도 유지한다. 이전 검색 응답은 무시한다.
- 방문 기록 권한을 거절하거나 나중에 해제하면 자주 방문한 사이트에서 주소 추천을 제공한다. 결과가 없으면 한 줄로 표시한다.

## Behavior Spec

1. 그룹이 없는 채팅의 선택기에는 `현재 탭`, `저장된 탭그룹`, `검색`을 둔다. 현재 탭이 기본이다. 기존 `#` 트리거 뒤에 글자를 입력하거나 `검색`을 고르면 검색 목록을 연다. 열린 그룹이 있는 채팅에서도 `#` 뒤 입력은 같은 목록을 연다. 검색어는 커서 앞의 활성 `#` 구간에서 읽으며 한글과 공백을 포함할 수 있다.
2. 입력창 바로 위에서 `주소 추천`과 `딥링크`를 함께 보여준다. 두 결과를 하나의 가로 목록으로 합친다. 같은 URL에는 딥링크의 정지 화면과 설명을 붙인다. 주소나 사이트 이름이 맞으면 앞에 둔다. 좌우 키로 선택하며 아래에는 현재 항목의 미리보기 한 개를 보여준다.
3. 주소 추천은 현재 확장에 있는 `topSites` 결과로 시작한다. 방문 기록을 허용한 경우 확장에서 제목과 주소가 맞는 방문 페이지를 조회하고, 제목·도메인 앞부분 일치와 최근 방문을 기준으로 정렬한다. `history`는 선택 권한으로 선언하고 첫 홈에서 부여 여부를 확인하고 필요한 경우 브라우저 권한 버튼을 표시한다. 나중에 설정에서도 켤 수 있다.
4. 딥링크는 한글 조합 중인 글자도 검색어에 포함한다. 주소 추천은 바로 갱신하고 딥링크 API는 300ms에 최대 한 번 최신 검색어를 보낸다. 임시 API는 영화·쇼핑·AI 등 실제 페이지 약 20개의 제목, 설명과 별칭을 점수화한다. UI에는 제목, URL, 화면 이미지와 짧은 설명을 반환한다. 실제 서비스 연결 시 이 응답 형식에 맞추는 부분을 교체한다.
5. 결과를 고르면 활성 `#검색어` 구간만 한 사이트를 가리키는 칩으로 바꾼다. 칩과 공백만 있으면 탭그룹을 열고, 메시지와 함께 보내면 페이지를 연 뒤 에이전트에 연결된 탭룸 ID를 전달한다. 그룹이 열려 있으면 그 그룹에 탭을 추가하고, 없으면 해당 채팅에 새 그룹을 연결한다.
6. `Enter`는 현재 항목을 칩으로 넣고 선택기를 닫는다. `Shift+Enter`는 칩을 넣고 선택기를 열어 둔다. 검색 모드에서는 현재 결과를 유지하며 계속 입력하면 새 검색어로 갱신한다. 저장된 탭그룹은 항상 그룹 칩 하나로 넣는다.
7. 검색어를 입력한 상태에서는 상하 키를 눌러도 편집 커서가 이동하지 않는다. 한글 조합 중인 키 입력은 입력기가 처리한다. 활성 `#검색어`는 입력창에서 연한 파란 배경으로 표시하고, 선택기를 닫거나 칩을 넣으면 색을 지운다.
8. 현재 탭, 저장된 탭그룹, 검색은 같은 높이와 왼쪽 메뉴 위치를 사용한다. 키 안내는 같은 줄에서 `← → 이동 · Enter 추가 · Shift+Enter 계속 추가`를 표시한다. 빈 상태도 같은 공간 안에서 표시한다.

## Cost and Complexity

자주 방문한 사이트만 검색하면 확장이 이미 쓰는 API를 재사용할 수 있어 가장 간단하다. 방문 단계가 여러 개인 업무에서는 주소를 기억하기 어려우므로 딥링크도 함께 제공할 가치가 있다. 임시 API는 소량의 예시 데이터로 조회와 표시를 검증한다. 추가 작업이 필요한 부분은 열린 그룹에 사이트 칩을 연결하는 처리다. 기존 저장된 탭그룹 칩은 연결된 그룹에 추가하는 동작을 지원하지 않는다.

## Usability

기존 선택기의 모양은 유지하며, 검색에서는 제목과 도메인이 보이는 짧은 목록을 사용한다. 먼저 도착한 결과부터 같은 목록에 보인다. 늦은 응답이 합쳐질 때 이미 고른 사이트가 남아 있으면 위치를 이어서 보여준다. 검색 결과가 없더라도 왼쪽 메뉴를 같은 자리에 둔다. 버튼과 키보드의 선택 결과는 같다.

## Risks and Mitigations

- 입력과 응답 순서가 뒤바뀌면 현재 검색어와 일치하는 응답만 반영한다.
- 방문 기록은 Chrome 확장 안에서 조회한다. 딥링크 API에는 현재 검색어만 전달한다.
- API의 URL은 사이트 칩을 만들기 전에 HTTP(S) 주소인지 확인하고, 실제 브라우저 탭은 사용자가 입력을 확정할 때 연다.

## Decision

검색 상자 하나에서 조회한 두 검색을 같은 가로 목록에 표시한다. 검색은 기존 입력창과 사이트 칩을 재사용한다. 닫힌 출처 탭을 기존 탭룸 ID로 복원하는 작업은 별도 항목으로 둔다.

## MVP Scope

주소 추천, 선택형 방문 기록 검색, 예시 데이터로 동작하는 로컬 딥링크 API, 키보드와 클릭 선택, 기존 그룹 또는 새 그룹으로 사이트 칩 열기를 포함한다.

## Success Metrics

- `#n`으로 주소 후보를, `#영화 예매`로 실제 사이트 딥링크를 찾을 수 있다.
- `Shift+Enter`로 현재 탭, 저장된 탭그룹, 검색 결과를 한 번의 선택기 열기에서 이어서 추가할 수 있다.
- 두 종류 결과가 같은 목록에 나타나며, 늦은 응답이 선택을 옮기거나 이전 검색 결과를 덮어쓰지 않는다.
- 권한 거부, `#` 삭제, 한국어 조합 중 Enter가 각각 정한 동작대로 처리된다.
- 검색 결과 선택 시 탭은 열리지 않는다. 최종 확정하면 그룹 유무에 따라 탭 하나가 열리고 메시지 안의 칩이 그 탭을 가리킨다.

## Open Questions

실제 딥링크 서비스를 붙일 때 API 주소, 인증 방법, 응답 필드와 관련도 기준을 확인한다. 임시 API에는 예시 업무 페이지와 별칭을 사용한다.

## Next Actions

기존 `#`의 검색 구간과 결과 목록을 먼저 연결한다. 그다음 확장 방문 기록 검색과 로컬 딥링크 API를 붙인다. 마지막으로 기존 그룹 안에서 새 사이트 칩을 여는 경로를 연결하고 일반 Chrome에서 위 시나리오만 확인한다.
