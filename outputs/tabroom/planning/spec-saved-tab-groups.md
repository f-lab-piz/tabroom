# 저장된 탭그룹과 새 채팅 시작

## Problem

현재 저장된 탭 묶음은 왼쪽 목록에서 별도의 채팅을 즉시 연다. 기존 채팅의 그룹을 복원하면 Chrome 탭 ID가 바뀌어 채팅 기록의 탭 카드가 끊긴다. 화면을 열기 전에는 저장된 탭의 구성을 한눈에 알아보기 어렵다.

## Target User

새 채팅을 시작하거나 닫아둔 업무 세션을 이어서 쓰는 탭룸 사용자.

## User Value

탭 구성을 보고 고른 뒤 작업 내용을 적어 전송한다. 같은 그룹을 다시 열었을 때 예전 채팅의 탭 카드도 계속 사용할 수 있다.

## Use Cases

- 새 채팅 첫 화면 왼쪽에서 **저장된 탭그룹**을 골라 입력창에 칩을 넣고, 오른쪽 **자주 쓰는 작업**에서 문구를 골라 조합한다.
- 열린 그룹이 없는 채팅에서 `#`과 방향키로 저장된 그룹의 화면을 확인하고 칩으로 넣는다.
- 사용자가 에이전트에게 현재 그룹을 저장하거나 저장된 그룹을 이 채팅에서 열어달라고 요청한다.

## Corner Cases

- 복원 전과 같은 주소가 여러 탭에 있어도 각 탭의 참조 ID를 유지한다. 의도적으로 닫은 탭, 교체로 사라진 그룹, 옛 연결을 확인할 수 없는 기록은 다른 탭으로 연결하지 않는다.
- 선택 취소나 전송 실패 시 탭을 남기지 않는다. 다른 그룹이 이미 열렸다면 그 상태를 확인하고, 복원 기록을 덮어쓰지 않는다.
- 캡처를 껐거나 이미지를 얻지 못한 탭은 제목과 사이트 아이콘을 표시한다. 이미지가 없어도 그룹 선택과 전송은 가능하다.
- 저장된 그룹이 없으면 첫 화면과 선택기에 짧은 빈 상태만 보여준다.

## Behavior Spec

1. 채팅 카드와 에이전트가 같은 탭룸 참조 ID를 사용한다. 브라우저 도구는 목록·생성·그룹 만들기·탭 선택에 탭룸 ID를 노출하고, 확장 브리지가 실제 Chrome 호출을 할 때 현재 Chrome ID로 변환한다. 에이전트에 노출된 Chrome 프록시의 인자·결과·이벤트도 탭 ID를 같은 방식으로 처리한다. 에이전트는 탭룸 ID로 페이지에 연결하며, 실제 디버거 연결은 탭의 현재 상태에서 얻는다. 복원 시 각 탭의 참조 ID를 새 Chrome 탭에 매핑한다. 묶음으로 새 그룹을 열면 새 ID를 발급한다.
2. `#`은 열린 그룹 없는 채팅에서 기존 호형과 **현재 탭**으로 시작한다. 호형 옆에 **현재 탭**과 **저장된 탭그룹**을 글자로만 세로 배치한다. 상하로 종류를 바꾸고, 저장된 탭그룹 단계에서는 호형 위의 그룹 이름을 좌우로 고른다. 아래에는 해당 그룹의 탭 화면을 저장 순서대로 표시한다. Enter로 그룹을 칩 하나로 넣는다.
3. 저장 시 탭별 가로 320px 정지 이미지를 기존 캡처에서 받아 로컬에 저장한다. 기존 프레임이 없으면 필요한 탭에 한해 한 장을 요청한다. 캡처 OFF는 존중한다. 저장 그룹을 둘러보는 동안에는 스냅샷 이미지를 읽는다.
4. 새 채팅 첫 화면 왼쪽에 저장된 탭그룹 목록, 오른쪽에 자주 쓰는 작업 목록을 둔다. 그룹 이름을 누르면 이 입력창에 묶음 칩이 들어간다. 작업 문구를 누르면 입력창에 넣으며 칩과 작성 중인 내용을 유지한다. **편집**으로 문구를 바꾸고 같은 Chrome 프로필에서 유지한다.
5. 묶음 칩으로 메시지를 보내면 지금 채팅에 탭을 열고 저장 순서대로 그룹을 만든다. 성공 시 복원 스냅샷을 새 그룹으로 바꾼다. 기존 왼쪽 채팅 사이드바의 묶음으로 새 채팅을 즉시 여는 흐름은 제거한다.
6. 에이전트의 `saveTabBundle`, `listTabBundles`, `loadTabBundle`은 UI와 같은 저장소와 동작을 사용한다. 각 호출의 목적을 표시하고, 성공한 불러오기 직후 에이전트의 브라우저 범위를 새 그룹으로 전환한다.
7. 자주 방문하는 사이트는 탭 하나짜리 칩으로 다룬다. 현재 탭 칩과 묶음 칩은 한 번에 같은 Chrome 그룹으로 연다. 선택기를 닫은 뒤 탭 관련 칩과 공백만 있으면 버튼과 Enter는 **탭그룹 열기**로 동작한다. 텍스트나 스킬 칩은 에이전트 요청을 전송한다.
8. 홈에서 그룹을 열면 사용 중인 탭룸 ID로 그룹과 채팅을 저장한다. 대화 기록은 빈 상태이며, 기존 채팅에 그룹을 열면 그 채팅에 연결한다. 첫 실제 전송 시 저장된 그룹을 이어서 쓰고 Codex 대화와 제목 갱신을 시작한다.

## Cost and Complexity

호형 렌더링과 탭 캡처를 재사용한다. 비슷한 사이트 탭을 알아보기 쉽게 정지 이미지 한 장을 추가한다. 미리보기 데이터를 모델 입력과 분리한다. 브라우저 도구의 기존 이름을 유지하고, 브리지에서 탭 ID를 받거나 돌려주는 경로에 변환을 집중한다.

## Usability

기존 밝은 화면과 호형을 기준으로 한다. 종류와 그룹 이름은 글자 강조만 쓴다. 화면을 틀과 카드로 더 나누지 않는다. 필요한 키 안내는 선택 중에만 한 줄로 둔다. 좁은 채팅에서는 첫 화면의 두 목록을 세로로 읽을 수 있다.

## Risks and Mitigations

Chrome ID 재사용이나 URL 일치만으로 과거 참조를 복구하지 않는다. 스크린샷은 Chrome 프로필의 로컬 저장 데이터로 관리하며, 한 탭당 한 장으로 제한한다. 그룹 생성이 중간에 실패하면 이번에 연 탭만 정리한다.

## Decision

첫 화면 기본 문구는 다음 세 개다.

- 이 탭들의 핵심 내용을 요약해줘
- 이 탭들의 공통점과 차이점을 비교해줘
- 다음에 할 일을 체크리스트로 정리해줘

## MVP Scope

탭 참조 유지, 기존 호형의 저장된 탭그룹 선택, 정지 이미지, 새 채팅 첫 화면, 에이전트 도구를 한 번에 적용한다. 이미 열린 그룹에 저장 그룹을 추가하는 동작은 이번 범위에서 제외한다.

## Success Metrics

복원 전후 채팅 카드와 에이전트가 같은 참조 ID로 같은 논리적 탭을 연다. 교체한 그룹과 다른 세션의 탭에 예전 ID로 접근할 수 없다. 첫 화면과 `#` 양쪽에서 선택 단계에는 탭이 열리지 않고, 전송 후 같은 채팅에 한 번만 열린다. 에이전트가 UI에서 저장한 그룹을 열고 바로 해당 탭을 조회할 수 있다.

## Open Questions

필수 선결 결정은 없다. 기존 기록은 실제 연결이 확인되는 범위에서 옮긴다.

## Next Actions

탭 참조와 공통 그룹 작업을 먼저 구현하고, 선택기와 첫 화면을 연결한다. 마지막으로 에이전트 도구와 가이드를 붙인 뒤 실제 Chrome에서 복원, 선택·전송, 에이전트 연동만 확인한다.
